⚠️ READ THIS FIRST — THIS IS GATED ON PURPOSE
  This bundle adds row-level tenant isolation to the FIVE money models — the ones that hold cash and
  the general ledger. A mistake here is the worst kind (money vanishing or crossing tenants), so it is
  deliberately sequenced BEHIND a green test suite. Do NOT deploy this until:

     1. Stage 1 (the tenant-isolation test harness) is deployed, and
     2. `php artisan test --filter=TenantIsolation` runs GREEN on your server.

  If your `php artisan test` still only shows the 2 example tests, Stage 1 isn't deployed yet — deploy
  that first (see "STAGE 1 — GET TO GREEN" below), confirm green, THEN come back to this bundle.

WHAT THIS CHANGES
  Adds `use App\Models\Concerns\BelongsToTenant;` to the last five unscoped tenant-owned models:
     CustomerPayment · OrderCost · LedgerAccount · LedgerJournal · LedgerLine
  This drives the KNOWN_UNSCOPED backlog to ZERO (history: 24 → 11 → 8 → 3 → 0). After this, every
  tenant-owned model is isolated; only the three permanent platform models stay global by design.

THE TRAP THIS BUNDLE HANDLES (why it's more than a one-line trait add)
  Once a model is scoped, any query with NO active tenant context silently filters to `tenant_id IS NULL`
  and returns nothing — and an explicit `->where('tenant_id', $id)` does NOT rescue it. The money models
  are read by CLI repair/backfill commands that had no tenant context. Each of those is patched to set an
  active TenantContext for the tenant it processes, BEFORE it touches the models:
     • AuditPaymentsCommand      (cash:audit-payments)   — set ctx after --tenant resolves
     • FixPaymentsCommand        (cash:fix-payments)     — set ctx before the forward AND rollback paths
     • RepriceForeignCashCommand (cash:reprice-foreign)  — set ctx before reprice AND rollback
     • LedgerBackfill            (ledger:backfill)       — set ctx per tenant inside its loop
  (BosDemoCommand already set context; EnableOrderSystemCommand never queries these models — untouched.)
  Request-path readers — CashService, LedgerController, the collect endpoint — already run with the
  tenant context set by middleware, so scoping is transparent there (and adds defense in depth).
