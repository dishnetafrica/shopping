──────────────────────────────────────────────────────────────────────────────
1. THE FIX — bot not sending the quotation PDF  ★ your reported issue
──────────────────────────────────────────────────────────────────────────────
WHAT WAS HAPPENING
  The AI (gpt-4o-mini) was TYPING OUT the quotation as a chat message — even
  inventing a fake number like "Quotation ORD-Q260722-D4NW" — instead of emitting
  the hidden <<QUOTE>> line that actually triggers the real PDF. No <<QUOTE>> line
  = no PDF built = customer gets prose, never the branded document.
  Diagnosis: bot_events showed stage `marker_missing` on EVERY quote attempt.

THE FIX (two layers, both in AiBrain.php)
  • RECOVERY (the real fix): when the model says "quotation/quote/proforma" but
    forgets the <<QUOTE>> line, the bot now runs a focused extraction call to
    rebuild the items from the conversation + the product it just showed, then
    RE-RUNS the real pipeline with a synthesised marker. The customer's prose is
    replaced with one clean line and the genuine numbered PDF is sent.
      - If the customer named a clear product but no amount, recovery quotes
        quantity 1 (a unit-price quote) — it does NOT invent a big number.
      - It can ONLY quote items that match a priced product in YOUR catalogue,
        so recovery can never send a wrong/hallucinated item.
  • PROMPT HARDENING: the model is now told, in hard terms, to NEVER type the
    quotation itself, NEVER invent a quotation number, and to emit <<QUOTE>> in
    the SAME reply when the product is clear (even a single unit).

WHY IT'S SAFE
  - Loop-safe: the re-run sees the <<QUOTE>> marker and takes the normal path —
    it can't re-enter recovery.
  - The MOQ interaction is handled: recovery may quote qty 1, and if a product
    has a minimum order (e.g. Galaxy Pack MOQ 5) the system rounds up to 5 for
    the price — the anti-hallucination guard (item 2) reads the REQUESTED qty,
    not the rounded one, so it never mis-fires on a legitimate MOQ bump.

──────────────────────────────────────────────────────────────────────────────
2. BOT — never invent quantities/products (the "50 bags nobody asked for" fix)
──────────────────────────────────────────────────────────────────────────────
When a customer listed items with NO amounts ("rice, oil, beans and sugar"), the
bot used to invent "50 bags x 25kg Basmati" etc. and quote goods never requested.
  • Prompt rule: if items are listed without quantities, ASK "how many of each?"
    and do NOT emit <<QUOTE>>.
  • Code guard (the real net): before a quote is sent, if a line's REQUESTED
    quantity is > 1 but the customer's own words (this message + last 6 inbound)
    contain NO number at all (digits, Arabic-Indic digits, or a spelled number),
    the bot asks for the real amounts instead of sending an invented quote.
    Fail-safe: it can only DELAY a quote to ask — never send a made-up one. It
    never blocks a single-unit price check (qty 1).

──────────────────────────────────────────────────────────────────────────────
3. USD-SHOP SAFEGUARD — a USD shop is always treated as native
──────────────────────────────────────────────────────────────────────────────
Makes the "$66 shown as UGX 66 / quote USD 0.00 / order $0.27" family of bugs
impossible to recur — even if currency_basis is wrong or unset. A USD-base shop
has its prices IN USD, so it's native by definition; the code no longer assumes
such a shop stores UGX and divides by the FX rate.
  • SalesBaseCurrency::nativeCurrency, CapabilityContext::nativeCurrency: USD base
    resolves to USD.  PanelCurrency::payload: USD base renders "plain".
NO EFFECT on UGX/SSP shops, and a NO-OP for you (already currency_basis=native) —
pure insurance so it can't slip back. Test currency-basis.test.php: 5/5 pass.

──────────────────────────────────────────────────────────────────────────────
4. WEEKLY DEMAND REPORT — what customers asked for that you don't stock
──────────────────────────────────────────────────────────────────────────────
New command demand:weekly sends a short WhatsApp to the owner every Monday 08:00
(Kampala) listing, from the AI's nightly learning log: items customers asked for
that didn't match your catalogue (purchasing signal) + questions the bot handled
poorly. Only sends if there's something to report. Opt-in via relationship_memory
(already ON for you). Extra recipients via the `demand_weekly_numbers` setting.
