BACKEND (tiny, read-only, no money path, no migration):

  OrderCostController::nav()  -> returns { ok, is_owner, role, menus:[effectiveMenus] }
      Only exposes the caller's OWN menu keys. Nothing writable.

WHAT EACH ROLE NOW SEES IN THE BOTTOM BAR:
  purchaser (Jayesh) : Orders · Buy · Cash        (no P&L, no Approvals pill)
  field (Asish)      : Orders · Buy · Cash
  sales              : Orders                       (no purchasing, no cash)
  manager / owner    : Orders · Buy · Cash · Book · Spend · P&L  + Approvals pill
  (if /papi/me/nav ever fails, it safely falls back to Orders · Buy · Cash only)

Tab -> access rule (must match server intent):
  Orders -> menu 'ordercosts'  |  Buy -> menu 'purchases'  |  Cash -> menu 'cash'
  Book / Spend / P&L -> owner/manager only   |  Approvals pill -> menu 'approvals'

#2 AMOUNT ECHO (book_cost, expenses, trade_cashbook = #amt ; orders = #total):
  - types are grouped live: 4000000 -> 4,000,000
  - a green box under the field echoes "UGX 4,000,000" so a stray zero is obvious
  - SAFE: calc() and save() already strip commas before use (verified), so the
    grouped display never reaches the API — the posted value is digits only.
