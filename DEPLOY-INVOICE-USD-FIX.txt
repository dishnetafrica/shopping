WHY IT HAPPENED  (your "why why?")
  Your catalogue is in USD: Popcorn Seeds 1kg = $2.20, Aluminum Foil Medium = $66.
  The invoice printed 8,041 and 241,230 — those are the USD prices × 3,655 (the UGX rate).
  So the numbers were UGX, but the document stamped a "USD" label on them WITHOUT converting.
  Correct total: 50×$2.20 + 10×$66 = USD 770.00  (not USD 2,814,350).

  Root: the Ciano SALES ORDER is a LEGACY order — created before we switched the shop to
  USD-native — so its line prices were stored in UGX. New orders are already fine (the
  quote→order path no longer converts for a USD shop). The problem is only OLD orders being
  invoiced now: the invoice labels their UGX numbers "USD".

  There WAS a built-in converter meant to catch exactly this, but the earlier USD-native
  safeguard made the currency helper report the shop's local currency as "USD" — which set
  the conversion rate to 1 and silently disabled every UGX→USD conversion. That defeated
  three places at once. This bundle fixes all three.

FILES CHANGED (3 + this note)
  app/Services/Invoicing/InvoiceService.php                 (issued invoice: born-USD convert)
  app/Http/Controllers/Panel/OrderInvoiceController.php     (quick/preview PDF: same convert)
  app/Http/Controllers/Panel/PanelApiController.php         (bulk remediation endpoint fix)

WHAT EACH FIX DOES
  1) InvoiceService::toUsdIfNeeded — when a USD-base shop issues an invoice, it detects whether
     the incoming amounts are actually UGX/SSP (by comparing the total to the USD-catalogue total
     at the real UGX and SSP rates, NOT via the helper that now returns USD) and, if so, divides
     every money field to USD. Strict NO-OP when the amounts are already USD. Now runs for any
     USD-base shop, not only ones carrying an internal flag.
  2) OrderInvoiceController::pdf — the quick, un-numbered "preview" invoice (/papi/order-invoice-pdf)
     rendered directly and skipped the converter, so it would still show UGX. It now applies the
     exact same normalization, so preview and issued invoice match.
  3) /papi/normalize-invoices-usd — the one-time tool that fixes invoices ALREADY stored. It was
     also disabled by the same helper (rate became 1 → it divided by 1 → no change, then skipped).
     Pinned to the real local currency (UGX) so it converts legacy UGX-magnitude invoices and sets
     the house-rule flag.
