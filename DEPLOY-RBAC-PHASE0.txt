PHASE 1 — OBSERVE (report-only)
  Set env RBAC_MODE=report  ->  rebuild  ->  php artisan config:clear
  The gate now LOGS (channel: stack, tag 'rbac.would_deny' / 'rbac.unmapped') every request a real RBAC
  would deny — but blocks NOTHING. Watch the logs 1–2 weeks:
    • rbac.would_deny for a LEGITIMATE user  -> fix Access::MATRIX (add that role to the action).
    • rbac.unmapped on a sensitive route     -> add it to config/permissions.php.
  Iterate until the report log is quiet for real traffic.

PHASE 2 — ENFORCE
  Set env RBAC_MODE=enforce -> rebuild -> config:clear. Mapped routes now 403 a disallowed role
  (owner/super-admin always pass; gate errors fail open). Money, deletes, admin are already mapped.

KILL SWITCH
  Set RBAC_MODE=off at any time to instantly disable the gate everywhere. No redeploy of code needed —
  just the env change + config:clear.

SAFETY
  Additive files; the request pipeline is untouched until you do Phase-0 step 2, and even then the gate
  is a pass-through until RBAC_MODE leaves 'off'. Built on the existing Access allow-list — one source of
  truth for action permissions, not a parallel system.
