TENANT ISOLATION — remediation batch 2: scope 3 more models + patch their commands (Constitution v1.0 · P0 Security)
==================================================================================================================

WHAT THIS DOES
  Scopes SourcingRequest, FollowupProposal, BotMiss with BelongsToTenant — but FIRST patches the
  scheduled commands that query them with no tenant context, because once a model is scoped a no-context
  query returns nothing (the scope ANDs `tenant_id IS NULL`, and an explicit `where('tenant_id',$t)`
  does NOT rescue it). Isolation debt: 11 -> 8. Remaining 8 = the money five + 3 platform-by-design.

THE PATCH PATTERN (why this is safe)
  Each scheduled command already loops `foreach ($tenants as $t)`. We set the active tenant at the top
  of that loop:  app(\App\Support\TenantContext::class)->set((int) $t->id);
  That makes every query in the loop (and in services it calls, e.g. GoalEngine) correctly scoped to $t.
  Queries already wrapped in withoutGlobalScopes()/withoutGlobalScope('tenant') (Order, Conversation,
  CustomerProfile) are unaffected. So the change can only make things MORE correct, never less.
  One read is cross-tenant BY DESIGN (the bot:misses ops digest) — it now says so with an explicit
  withoutGlobalScopes().
