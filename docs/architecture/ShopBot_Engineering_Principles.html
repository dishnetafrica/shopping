Engineering Principles

v1.0

Five rules. Check every pull request against them. If a change can’t pass all five, it isn’t ready to merge. This is the whole operating manual — the Constitution says what’s true forever, the Blueprint says what to build for sixteen weeks, and this page is what you hold in your head every day.

The five principles

  1. One business effect → one capability.
    Money-in has exactly one owner. Trade, custody, FX — each has exactly one. Never a second path recording the same fact. (This is the Rule of One.)
  2. Business rules live in the kernel.
    Not in the AI, not in a controller, not in the UI. If it’s an invariant, a capability enforces it — everywhere, or nowhere.
  3. Events are immutable.
    You correct the world by adding a compensating event, never by editing or deleting one. History is not editable.
  4. AI never bypasses the kernel.
    The agent may read the Twin and invoke a capability. It may not touch a table or emit an event any other way. Swap the model freely; the rules don’t move.
  5. Complexity must buy differentiation.
    If a feature adds complexity without widening the moat, don’t build it. Boring is a valid — often correct — answer.

What is event-sourced, and what stays simple — the hybrid kernel (amends Blueprint Part 1)

L1 · EVENT-NATIVE
Money · Custody · Trade lifecycle · AI actions
History is the value: append-only, replayable, auditable. Only these are event-sourced.
L2 · STATEFUL
Product · Category · Branch · Tax · Settings · User preferences
Normal relational models. No value in replaying a product description — keep it boring.
L3 · DERIVED
Dashboards · Reports · KPIs · Predictions · the Twin
Projections, rebuilt from L1 events + L2 state. Never authoritative.

Rule: an object is event-sourced only if it is L1. Do not force L2 entities into the event model to feel consistent — that is complexity without differentiation (Principle 5).

The migration covenant

Every week must leave the product more usable than the week before. Ship user-visible value, not just plumbing. Architectural progress that a user can’t feel is how infra rebuilds get cancelled in week seven.
Wk 3 → fewer payment errors  ·  Wk 5 → cash reporting you can trust  ·  Wk 8 → simpler trade flow  ·  Wk 10 → better shipment tracking.
Operating mode from here: The Constitution (Articles I–IX) and the Blueprint are frozen. Every conversation now begins: “We are implementing Week X.” We redesign the architecture only when a real implementation problem proves an assumption wrong — not before. The work has shifted from inventing to building.
