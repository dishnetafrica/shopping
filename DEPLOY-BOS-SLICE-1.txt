DEPLOY — BOS v1.0 Slice 1: Business Foundation (event spine + rule engine + projections + SDK)
==============================================================================================
Pure OVERLAY. New code under a new namespace (app/BOS/) + ONE new table. Nothing existing is
touched, and nothing writes to the new table yet — so deploying this changes zero live behaviour.
It's the spine the sales journey (Slices 2-3) is built on.

REVIEW CHANGES APPLIED (pre-merge): (1) legacy→spine strategy + bridge (ADR-012); (2) rule engine
mandatory + fitness guard (ADR-013); (3) projections capped at 4 canonical types (ADR-014);
(4) every event instrumented from day one (ADR-015). The bos_events migration now includes the
instrumentation columns — it is still ONE new table, still inert on deploy.

DEPLOY
  git add database/migrations/2026_07_23_000001_create_bos_events_table.php app/BOS tests/Unit/Bos tests/Feature/Bos
  git commit -m "BOS v1.0 Slice 1: event spine + rule engine + projections + SDK (overlay)"
  git push  ->  EasyPanel Rebuild
  Then run the migration (EasyPanel terminal):   php artisan migrate

VERIFY
  1. Table exists:   php artisan tinker --execute="dump(Schema::hasTable('bos_events'));"   -> true
  2. Tests pass:     php artisan test --filter=Bos
                     -> BusinessRuleTest (rules) + ArchitectureFitnessTest (architecture) all green.
  3. Append-only proof (optional):
       php artisan tinker --execute="try{ \$e=App\BOS\Event::first(); if(\$e){\$e->name='x';\$e->save();} echo 'NO-GUARD'; }catch(\Throwable \$x){ echo 'guard OK: '.\$x->getMessage(); }"
  4. Inert check: no existing screen or number changes (nothing emits yet).

WHAT THIS UNLOCKS
  Slice 2 (Today) and Slice 3 (Customer Journey) build on Bos::emit()/timeline(). The first real
  events (PaymentReceived, InvoiceIssued, QuoteCreated) get emitted from the existing services in
  Slice 3 — at which point the Customer Timeline lights up from data you already produce.

ROLLBACK
  php artisan migrate:rollback   (drops bos_events; the migration has a working down())
  Remove app/BOS + tests/Unit/Bos + tests/Feature/Bos + the migration file. Zero impact — nothing
  in V3 references them.

CI (recommended)
  Wire `php artisan test --filter=Bos` into your build. From now on, architecture drift fails the
  build instead of slipping through review (the four-review gate, doc 9).
