Kernel Implementation Blueprint

v1.0 — EXECUTABLEConstitution I–IX: FROZEN

The Constitution is immutable and is not redesigned here. This document does one thing: turn Articles I–IX into engineering decisions against the real repository — every model, controller, table and file gets a destination. It is written to be handed to engineers and executed week by week.

Scope of the live repo mapped here: 112 models · ~119 tables · 77 controllers · 45 capabilities · 31 service namespaces. Nothing is left unmapped.
The Rule of One — the governing law of this migration (operationalizes Constitution Art. IV)

Every business effect has exactly one owner: one capability, emitting one canonical event, feeding one projection. Never again five code paths recording the same fact.

PanelApiController (7,580 lines / 173 methods) is dissolved, not refactored. Part 4Migration Order — real weeks, not a roadmap

Sixteen weeks. The first six are also the due-diligence money & tenancy fire drill — the two efforts are the same work.
  1. Freeze & scaffold. Tag Constitution v1.0 immutable. Create app/Kernel/{Events,Objects,Capabilities,Projections,Twin,Rules,Registry}. Stand up CI running the existing 132 test files. Delete the 3 duplicate trees (root /Http, root /Services, root /seller.html) — zero-risk, ends "fixed the wrong copy."
  2. Harden the event envelope. Extend the existing BOS/EventStore with the Constitution envelope (versioned type, prev_hash, schema validation, provenance). Register the money.received schema. Freeze PanelApiController.
  3. Build the one money.receive capability. PaymentService::record() now emits money.received (dual-write: still writes the table, also appends the event). Seed invariants from the existing BOS/Rules (PaymentNotExceedBalance, ReceiptRequiresPayment).
  4. Kill the second money path. Route StaffCashController, PaymentsManagerController and invoice-pay through money.receive. Add the idempotency key on every money-in. closes the DD Fatal double-record
  5. Cash projection + Twin cash surface. Build the cash/Money projection purely from money.* events; flip cash-position & P&L reads to the projection. Prove sum(events) == projection.
  6. Tenancy hardening. Make TenantContext request/job-scoped; reset super-admin at job start/terminate; make BelongsToTenant throw on null-tenant writes; flip perm_enforce default-ON. closes the DD tenant-leak
  7. Trade family — capabilities. trade.quote/place/invoice/fulfil/settle; Order/Invoice/Quotation writes emit trade.* (dual-write).
  8. Trade projection. Rebuild Order+Invoice+Quotation+CreditNote as one Trade read-model; flip trade screens to read it.
  9. Custody family. Shipment state machine emits custody.*; custody.transfer capability owns all stock/box movement (absorbs StockMovement, Consignment, Delivery legs).
  10. Custody projection + Twin custody map. Who holds what, on which leg, now — the differentiated surface. Add the box-conservation invariant test.
  11. Party + Item projections. Unify Customer/Supplier/Staff/Rider/Partner → Party; Product/Alias/Variant/Category → Item. Roles become attributes.
  12. Conversation as first-class. Bot webhook emits conversation.*; OrderDraft becomes Intent; a Trade can be born from a message end-to-end.
  13. One brain. Merge BotBrain/AiBrain/n8n into a single planner whose only kernel interface is (read Twin · list capabilities · invoke capability). AI is now swappable by contract.
  14. ERP becomes an adapter. A derived double-entry projection subscribes to money.*/trade.* and exports to QuickBooks/Odoo/CSV. Retire ledger_accounts/journals/lines as authoritative.
  15. Retire screens to inspectors. As capabilities cover each flow, port the remaining /panel/* pages into native V3 read-views; begin deleting seller.html + the desktop iframes.
  16. Carve & scale. Delete the last of PanelApiController; move to a worker pool (Horizon/Redis); commit config/queue+cache+database with a read-replica plan.

Part 7Mandatory Tests — the new definition of green

No capability ships without these. They are what makes an event-sourced money system trustworthy.
Test classAsserts
Event replayReplaying the full log from zero reproduces every current projection byte-for-byte. The log is the truth.
Projection rebuildDropping and rebuilding any projection yields the identical state — projections hold no hidden state.
Capability invariantsEach capability refuses illegal input: credit exceeded, negative stock, unrated-currency FX, receipt without payment (seed from existing BOS/Rules).
Idempotency Rule of OneThe same command key applied twice yields exactly one event and one state change — the offline-retry double-record can never recur.
Tenant isolationNo capability, projection or replay can read/write across tenants; super-admin is reset between jobs; null-tenant writes throw.
Money correctnesssum(money.*) == cash position; a reversal exactly offsets its original; no path records money-in except money.receive.
Custody conservationboxes taken == boxes handed over + in-transit + shortfall, per leg — the cross-border invariant.
Agent safetyThe agent cannot emit an event outside a capability; irreversible/over-threshold actions require a human even at autonomy=auto.
Execution stance: the Constitution says what is true forever; this blueprint says what to do for sixteen weeks. Every ticket is now phrased as "which capability, which event, which projection" — and if a ticket can't be phrased that way, it isn't ready to build. The first four weeks pay for themselves twice: they are the migration's foundation and the due-diligence money-integrity fix. Start there.
