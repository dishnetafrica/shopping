ShopBot · 10-Year Architecture

The Operating System for AI-Native Business

A business does not want 500 screens or 40 modules. It wants outcomes. So the product is not an app over a database — it is an agent over an event log, acting through a typed set of capabilities, under an autonomy policy the owner controls. Screens become optional inspectors. ERP becomes downstream plumbing.

The core business objects (the whole vocabulary)

Event

The immutable fact that something happened. Everything else is derived from it.

Party

Anyone you deal with — customer, supplier, staff, transporter — one object, many roles.

Conversation

The durable thread with a Party across any channel. The real interface object.

Intent

A captured desire ("send 39 boxes to Juba", "who owes me"). What the agent plans over.

Trade

One unit of commerce end-to-end: quote → order → fulfil → settle. Invoice/delivery are facets, not silos.

Item

What is bought/sold/moved — fluid identity the bot resolves from language, not rigid SKU discipline.

Money Movement

Every value event: cash in hand, person-to-person handoff, FX, settlement. The ledger is derived from these.

Custody

Who physically holds what, where, across cross-border legs. No ERP has this primitive.

Task

A unit of work routed to a person via a login-free link. Already right — keep it.

Capability

A thing the business can DO, with declared effects, reversibility and autonomy. The action primitive.

The five verbs — what happens to today's system

Keep unchanged

  • Capability registry + manifest + thin WorkspaceController seam
  • AiPolicy autonomy ladder + CommandBus
  • BOS event store / projections
  • The moat encoders: Discovery, Offers/OfferVision, custody engine, JobToken/TaskEngine
  • "One guarded write path" money principle

Delete completely

  • Screens-as-the-product: classic panel, desktop iframes, a Filament panel
  • PanelApiController god-object (carve, don't extend)
  • ERP positioning + hand-built PO/GRN/WMS/tax engines
  • The second parallel ledger
  • Form-based manual order entry as the default

Platformize

  • Money / ledger kernel (cash-native, API-first)
  • Event store as a streaming backbone
  • Omnichannel gateway (WhatsApp/voice/SMS)
  • Language / NLU model shared across tenants
  • Custody-trade engine · Pricing/FX · Documents · Identity

Make AI-native

  • The primary UI = intent over chat/voice
  • Onboarding = cold-start from the merchant's own chat export
  • Operations = agent-run loops under autonomy policy
  • Reporting = ask a question, not open a dashboard
  • Catalog & pricing maintained from signals

Let disappear

  • Modules & menus as the mental model
  • The master-data setup project
  • The user-facing general ledger
  • Role/permission matrices → autonomy + approval
  • Month-end batch → continuous reconciliation
The one line: ShopBot's next decade is not a bigger ERP — it is the operating system a small, informal, cross-border business talks to. The agent is the runtime, capabilities are its instruction set, the event log is its memory, and the owner sets how much the machine may do alone. Everything you'd call "ERP" retreats to the bottom of the stack, where infrastructure belongs.
