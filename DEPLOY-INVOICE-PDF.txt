DEPLOY — Professional wholesale INVOICE PDF (server-side, like the quotation)
============================================================================

THE PROBLEM
  "Export Invoice (PDF)" was just the browser printing the live editing screen (window.print).
  That's why the PDF showed form controls (Discount dropdown, "Delivery fee — enter manually"),
  browser chrome (date, https://mycloudbss.com/panel, "1/2"), and the "groceries delivered fast"
  quick-commerce tagline. It looked nothing like your clean quotation.

WHAT YOU GET NOW
  "Export Invoice (PDF)" builds a real, branded PDF on the server with dompdf — the SAME engine
  that makes your good-looking quotation — and opens it in a new tab. It is WYSIWYG: whatever you
  see on the order (line prices you tweaked, discount, freight/delivery, and the currency you've
  selected — UGX / USD / SSP) is exactly what prints. No form controls, no browser chrome, no
  Blinkit tagline. A proper B2B trade document:

    - Centred shop header (logo + name + address), contact line, TIN — same branding as the quote.
    - Big "INVOICE" title, "Bill To" business block (name, tel, address), Invoice No / Date /
      Currency / Status box.
    - Bordered line grid: #, Description (+ item code if any), Qty, Unit Price, Amount.
    - Totals: Subtotal, Discount (labelled with the % if you used percent), Freight / Delivery,
      TOTAL, then Amount Paid and a red "Balance Due" (or green "Paid in Full").
    - Terms + optional bank/payment details, and a "computer-generated, valid without signature"
      footer.

FILES
  app/Http/Controllers/Panel/OrderInvoiceController.php   [NEW]  builds + streams the PDF.
  routes/web.php                                          adds papi/order-invoice-pdf (get|post).

DEPLOY
  1. Replace the files above -> commit.
  2. EasyPanel REBUILD (no migration needed — this feature has no new tables).
  3. Open any order -> "Export Invoice (PDF)" -> a clean PDF opens in a new tab. Switch the
     currency (UGX/USD/SSP) and export again — the PDF follows the selected currency.

OPTIONAL BRANDING (tenant settings — all have sensible defaults, set only if you want to change)
  invoice_title    default "INVOICE"  (use "TAX INVOICE" if/when you register for VAT)
  invoice_terms    default retention-of-title + 48h claims wording
  bank_details     e.g. bank name / account no / mobile-money — printed under "Payment details"
  invoice_footer   default "Thank you for your business. ... valid without signature."
  (Header logo/name/address/tel/email/website/TIN reuse the SAME settings as your quotation.)

WHOLESALE EXTRAS (added)
  - Cartons/units on each line: the Qty column now prints the product's unit (e.g. "50 CTN",
    "20 BAG") when the product has a unit set — so a wholesale line reads "50 CTN" not just "50".
    Nothing to configure; it uses the unit already on each product. Products with no unit just
    show the number, as before.
  - Credit terms + due date: set invoice_terms_days (e.g. 14) and every UNPAID/part-paid invoice
    prints "Terms: Net 14 days", a bold "Due Date", and a "Payment terms" line. A fully-paid
    invoice prints "Paid in full" and no due date. Per-order override: post terms_days.
      invoice_terms_days   whole days of credit (default 0 = due on receipt)
      credit_terms         override the auto credit sentence if you want your own wording

  - Per-carton PRICE column: when a product has a pack size (pcs per carton), the invoice adds a
    "Pack" column (e.g. ×24) and prints the per-piece price under the carton price
    ("180,000  = 7,500 /pc"), so a buyer sees both the carton and the piece rate. A plain
    single-piece invoice (no pack sizes anywhere) hides the column and looks unchanged.

  - New orders default to CARTONS: when you add a product that has an MOQ set, the quantity
    defaults to that MOQ (the carton minimum) instead of 1 — in both the order "Add item" box and
    the POS grid. The Add dropdown now shows the unit + "min N" next to each product. Products
    with no MOQ still default to 1, exactly as before. (MOQ/unit/pack are set per product under
    Products → "Bulk set unit / pack / MOQ", or on each product.)

--------------------------------------------------------------------------------
PART CARTONS (loose pieces) — "sometimes we supply less than a full carton"
--------------------------------------------------------------------------------
The clean rule: per-piece price = carton price ÷ pieces-per-carton (pack size). So a partial
supply is just a line billed in PIECES at that rate. This is now built in:

  SELLER PANEL (order "Add item"): a new "Unit" selector — Carton or Piece (loose).
    - Carton  -> full carton price, qty defaults to the carton minimum (MOQ). (as before)
    - Piece   -> the per-piece price (carton ÷ pack), qty in pieces. Only offered when the
                 product has a pack size (so we know pieces-per-carton).
    You can put BOTH on one order — e.g. "45 cartons" + "12 pieces" — as two separate lines,
    which is exactly how you invoice a part-carton shortfall or a small loose sale.

  INVOICE PDF: a carton line prints "50 CTN · ×24 · 180,000 (= 7,500/pc)"; a loose line prints
    "12 PC · 7,500". So the buyer sees cartons, the pack, the per-carton price AND the piece rate.

  WHATSAPP BOT quote: for any product sold by carton with a pack size, each quoted line now also
    shows the loose rate, e.g. "• 5 × Sugar carton = UGX 900,000 (loose: UGX 7,500/pc)", so a
    customer who wants less than a carton knows the piece price up front. (No change to how the
    bot reads quantities — it just shows the extra rate. To also auto-bump a below-minimum order
    up to the carton minimum, set moq_mode = roundup.)

FILES (added to this bundle for the above)
  app/Services/Bot/OrderCalculator.php   pack_size in the catalogue + per-piece line in the quote.

REQUIREMENT for part-carton pricing to work: the product must have a PACK SIZE (pieces per
carton) set. Products → "Bulk set unit / pack / MOQ" — set unit "carton", pack e.g. 24, min 1.
Without a pack size the Piece option is greyed out and the loose rate simply isn't shown.

--------------------------------------------------------------------------------
"WHICH PRODUCTS STILL NEED A PACK SIZE?" — a setup finder on the Products screen
--------------------------------------------------------------------------------
On Products you'll now see a red "⚠ N missing pack size" chip (only when some are missing).
  - Tap it -> the list narrows to just the products with no pack size. Tap again to clear.
  - Each product card shows either "carton ×24 · min 5" (good) or a red "⚠ set pack size".
  - Best workflow: tap the chip to show the missing ones, then tap "⚙ Unit/Pack" (top bar) —
    the bulk editor applies to exactly the products currently shown, so you can set unit/pack/MOQ
    for a whole batch in one go. Repeat per category until the chip hits 0.
When every product has a pack size, the chip disappears and carton + loose pricing works
everywhere (invoice, order entry, bot). This is UI-only in seller.html — no backend change.
